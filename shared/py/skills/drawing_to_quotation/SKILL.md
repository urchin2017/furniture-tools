# 图纸 → 御見積書（报价单）· V5（2026-07-02）

## 这一版为什么存在（先读懂三个病根）

V3 声称用几何测量根治"读到局部尺寸"，但 2026-07-02 石垣島美咲町案件暴露出它的盲区，
6 处外形尺寸全部出错、且与 V2 一模一样。复盘结论：

- **病根1：几何引擎对光栅图纸完全失效，且失效后没有强制兜底。**
  该案件 PDF 每页图纸本体是一张 3310×2340 的**位图**（CAD 导出成图片再排版），
  矢量层没有任何直线 → `measure_dims.py` 每页返回 `vector_ok=false` 直接短路，
  「几何量外形」从头到尾一次都没生效。而流程没有把"几何失效"当成硬报警，
  于是尺寸悄悄退化成了下面的病根2。
  **V5 修法**：`extract_scaffold.py` 显式判定光栅页（矢量层无线条＋整页大图）并打印
  `⚠ RASTER` 报警清单；只要出现光栅页，**必须**走「看图协议」（下文），禁止跳过。

- **病根2：文本层注记被当成了外形尺寸——这是最危险的陷阱。**
  很多图纸页角有一段文字注记（产品名/款号/数量/材质/`W… D… H…`）。它**看起来**像
  权威汇总，实际常是**局部/本体/分段尺寸**。该案件 6 处错误全部源于照抄注记：

  | 品番 | 注记(错误采用值) | 真实外形 | 注记实际含义 |
  |------|----------------|---------|-------------|
  | F04 | W600 | **W1200** | 台面分两段，600 是半块（图面外形线 1200=600+600） |
  | F05 | H1135 | **H1350** | 1135 只是靠背段（外形线 1350=150+1135+65） |
  | F10 | W1660 | **W1740** | 1660 是柜体，不含两侧フィラー40（40+1660+40） |
  | F11 | W980 H1920 | **W1020 H1950** | 柜体尺寸，不含フィラー40/顶部调整材30 |
  | F12 | H2610 | **H2650** | 柜体尺寸，不含顶部フィラー40（CH=2650） |
  | F14 | （无注记） | **H2550** | 页面无文本层，被拿 F13 的 H2000 凑数 |

  **V5 修法（铁律三）**：文本注记只写进 `text_dims` 当交叉参考，**绝不允许直接采用**。
  外形必须来自几何量取（矢量图纸）或看图读「最外侧尺寸链」；与注记不一致时，
  以图面为准，并在备考写明「※図面注記W600は分割寸法・外形はW1200」这类缘由，
  既保住正确值、又给对方复核线索。

- **病根3：造作(嵌入式)家具的外形惯例没被编码。**
  店铺造作柜的报价外形 = **含フィラー(填缝条/调整材)的安装外形**：
  W 取最外侧链（40+1660+40=1740），H 按 CH（天井高）基准（柜体2610+顶部40=2650=CH）。
  图面上的 `CH=xxxx` 注记、以及「最外侧那条含 40/30 小段的尺寸链」就是证据。
  **V5 修法（铁律四）**：遇到 WL/CL/FL 记号与フィラー的立面，外形取安装外形；
  柜体裸尺寸写进备考。独立家具（桌椅沙发）不受此条影响，取产品自身最外轮廓。

> **铁律一：外形 W/D/H 优先几何量取（仅矢量图纸有效）；光栅图纸必走看图协议。**
> **铁律二：一个品番 = 一行。F01 与 F01A 两行，各填各自数量，绝不合并。**
> **铁律三：文本层注记绝不直接当外形；必与最外侧尺寸链核对，不一致以图面为准并写备考。**
> **铁律四：造作家具外形含フィラー、H 按 CH 基准；柜体裸尺寸写备考。**
> **铁律五：拿不准就标 ⚠要確認，绝不静默写一个看似合理的数。**

## 数据管线（四步，顺序不可省）

```
① extract_scaffold.py   →  products.json 骨架 + pages/full_page_XX.png
     · 每页尝试几何量取（矢量图纸）并预置 measured；光栅页打 ⚠RASTER 报警
     · 每个品番各成一条记录（含「F07，07A」缩写展开）；W/D/H 一律 null
     · 解析 款号/数量（数量：2pcs / FXX：N台 / 共Npcs）预填 qty 候选
② 定外形尺寸（几何→看图，见下方协议）→ 填 W/D/H、qty、dim_source、dim_evidence
③ fill_quote.py         →  从 JSON 填 Excel，施加全部排版规范，另存新文件
④ render_check.py       →  渲染 PNG 逐页目视验证
```

`products.json` 字段见 `references/data_schema.md`。

## 输入 / 输出

**输入**：① PDF技术图纸（必需；矢量或光栅均可）；② Excel报价模板（必需）；
③ 产品照片文件夹（可选，没有就从图纸裁产品图）。

**输出**：① `御見積書_{项目}_v{n}_YYYY-MM-DD.xlsx`（不覆盖原模板）；② 渲染验证 PNG。

## 完整流程（SOP）

### Step 0 · 探索输入文件
`ls`/`glob` 识别 PDF、模板、照片文件夹，确认对应关系与项目名。
装依赖：`pip install pymupdf openpyxl Pillow numpy --break-system-packages`（验证还需 LibreOffice）。

### Step 1 · 生成骨架 + 光栅判定 + 整页图（extract_scaffold.py）

```bash
python3 scripts/extract_scaffold.py <图纸.pdf> <工作目录>/products.json \
    --img-dir <工作目录>/pages --dpi 150 --skip-pages 1 --project "项目名"
```

看输出报警：`⚠ RASTER` 页数 >0 → 几何测量不可用，直接按看图协议处理全部光栅页。
无文本层的页也会建占位记录（code 空），看图时补品番/品名。

### Step 2 · 定外形尺寸（★核心步骤）

**矢量图纸**（measured.vector_ok=true）——沿用 V3 优先级：
1. `confidence=high` 且 `suspect_local=false`、`extent_ok=true` → 采用 `overall_value`，`dim_source="geometry"`。
2. `suspect_local=true` / `extent_ok=false` → 用 `overall_by_extent` 并 Read 整页图核对。
3. `confidence=low` → 看图协议。

**光栅图纸 / 几何失效**（vector_ok=false）——**看图协议（V5 强化版）**：
1. 逐页 `Read pages/full_page_XX.png`（150dpi 起，看不清对该页重渲 300dpi 或象限放大：
   `python3 scripts/render_pages.py <pdf> pages --pages 7 --dpi 300 --zoom-quadrants`）。
2. 每个轴找**最外侧的尺寸链**：它位于视图最外圈、贯穿整个产品、
   常由多段组成（如 40+1660+40 或 150+1135+65），**链的总标注或各段之和 = 外形**。
   单独一条与页角注记相同的线段（600/1135/1660…）多半是局部——正是要避开的陷阱。
3. 立面有 WL/CL/FL/フィラー/調整材 → 造作家具，按铁律四取安装外形；
   `CH=xxxx` 注记是总高的强力旁证。
4. D（深度）看侧视图/断面图最外链。
5. 与 `text_dims` 对照：一致→放心；不一致→以图面为准，备考写明注记含义
   （分割寸法/本体寸法/部分寸法）。
6. 每条写 `dim_source="visual"` + `dim_evidence`（引用具体链，如
   「立面下端最外寸法線W1740（40+1660+40）／CH=3000」）。
7. 数量交叉核对：注记「数量：2pcs」与图框角「F04：2台」应一致，不一致标 ⚠。

**通用校验**：外形 ≥ 该轴任何局部值；(链求和≈外形)；整体 vs 部件冲突取整体。
品番在多页重复（如 F09 同时是 Counter 和 Shelf-02）→ 两行都保留，备考「品番重複・要確認」。
逐项核对清单见 `references/qa_checks.md`；本次实战案例全记录见
`references/case_ishigaki_2026-07-02.md`（**第一次用本技能前建议先读它**，10 分钟看懂全部陷阱）。

### Step 3 · 日中双语（空行分隔）
同 V3：C列=`日语\n\n中文`，E列逐条，N列备考。术语表 `references/translations.md`。
メラミン化粧板（フォーミカ）中文统一「防火板」。文本可能是 NFD，脚本已 normalize。

### Step 4 · 填 Excel（fill_quote.py）

```bash
python3 scripts/fill_quote.py --pdf <图纸.pdf> --template <模板.xlsx> \
    --json <工作目录>/products.json --out <工作目录>/御見積書_项目_v1_YYYY-MM-DD.xlsx \
    --project "项目名" --start-row 18 --last-row 50
# 终版加 --require-visual：有未确认项直接拒绝出版
```

排版规范见 `references/formatting_spec.md`（统一行高、裁图居中、数量列14pt粗体千位、
单价留空保留公式、⚠淡黄高亮）。

### Step 5 · 渲染验证（强制）

```bash
python3 scripts/render_check.py <御見積書_....xlsx> <工作目录>/check --area A1:N53 --dpi 110
```
逐页目视：拆行正确、尺寸与图面一致、备考的注记差异说明齐全、⚠行高亮、合计公式正常。

### Step 6 · 终审（V5 新增强制项）
用脚本把成品 16 行（或 N 行）的 品番/W/D/H/数量 与 products.json 逐项 diff，输出「一致 N/N」。
若用户提供了基准（旧报价/对比报告），一并逐项核对。发现不一致 → 回 Step 2。

### Step 7 · 安全保存
另存 `{项目名}_v{n}_{YYYY-MM-DD}.xlsx`，不覆盖原模板；要覆盖成品先 `cp` 时间戳备份。

## 常见问题

- **Q：图纸是扫描件/位图，几何测不了？** A：这正是 V5 的主场。scaffold 会打 ⚠RASTER 报警，
  之后全部走看图协议：读最外侧尺寸链，永远别信页角文字注记的 W/D/H。
- **Q：页角注记和图上尺寸线不一致，听谁的？** A：听图面最外侧尺寸链的。注记常是
  分段/本体/局部值（见案例文件的 6 个实锤）。备考里写明差异缘由。
- **Q：柜子紧贴天花/墙面，高度取哪个？** A：造作家具取含フィラー的安装外形（CH 基准）；
  柜体裸尺寸写备考。独立家具取自身最外轮廓。
- **Q：某页整页没有文字？** A：照样建行。品番看图框右下角（Drawing No.），
  规格参照同系列页（如 F14 参照 F13），总高用 CH 旁证，并在备考注明来源。
- **Q：同一品番出现在两页？** A：两行都保留，各自尺寸数量，备考「品番重複・要確認」。
- **Q：出来的和以前一样？** A：检查是否走了 extract_scaffold。fill_quote 只认 JSON，
  没有 JSON 直接报错，从结构上杜绝照搬旧数据。
- **Q：soffice 渲染慢/超时？** A：分页渲染或抽检最满行所在页。
